v0.4.4 / 运行中立即引导

工作到一半时，直接发文字，例如“先别改页面，先修测试”。这条文字会成为待办，提供立即引导、下一轮发送、取消三个按钮。立即引导通过原生 turn/steer 追加到原任务，不需要先停止；已完成的操作不会自动撤销。

选择下一轮发送后，等当前任务正常完成并释放 worker，再按收到顺序合并排队文字。超过单轮长度限制时分轮发送。未选择的待办不会自动执行；中止、失败、会话变化或桌面占用时暂停自动发送。

/pending 查看待办，/status 查看数量。待办仅保存在内存，30 分钟过期、重启清空，上限 20 条 / 60000 字符。当前支持文字，图片和文件仍需空闲时发送。/guide 是操作说明，不是运行中引导指令。

v0.4.3 / 工具确认与操作引导

Chrome/Computer Use 的基础 MCP 表单现在可以通过 TG 明确确认；简单的是/否及选项可直接点按钮，更多字段使用 /mcp 编号 {"字段名":"值"}。/mcp 查看待处理编号，/guide 按当前会话、任务和待确认状态给出下一步。运行中文字待办见 v0.4.4 说明。

URL 流程隐藏查询参数和片段，请先在 Mac 用原始链接完成操作，再点“已在 Mac 完成”。敏感输入或复杂表单需在 Mac 处理；工具的 API Key 鉴权限制和 macOS 系统权限仍单独生效。按钮超时或任务结束后失效。

v0.4.2 / 精简任务状态消息

任务开始时只发送一张“正在执行”状态卡；任务正常完成并确认临时 worker 已关闭后，原卡片直接更新为“已完成”，不再新增第二条重复状态消息。

成功状态保留 30 秒后自动删除，Codex 正文回复、图片和文件不会删除。中止、异常以及部分输出未能回传的提示会保留，避免重要信息被自动清理。极快任务也不会在完成后留下过时的“正在执行”消息。

v0.4.1 / TG 确认释放桌面占用

选择会话或发送任务时，如果发现桌面 writer 仍在占用，TG 会显示“确认释放桌面并由 TG 接管”和“取消”。确认按钮两分钟失效，并且不会自动补发刚才失败的任务。

确认后会先再次尝试恢复；占用已自然消失时不结束任何进程。仍被占用时，只匹配当前用户下、ChatGPT 主进程直属且路径完全一致的唯一 Codex 后端，同时排除 Bridge 自己的 worker。零个或多个目标都会拒绝；只使用 SIGTERM，不使用 SIGKILL，ChatGPT 窗口不会退出。

这是重启桌面 Codex 后端，不是协议级 writer 转移。桌面端所有正在执行的 Codex 任务、待审批和终端都可能中断；已经发生的文件和外部操作不会回滚。TG 接管后两分钟未收到任务会自动释放；任务结束也立即释放。/release 只释放 TG 自己持有的 writer。

v0.4.0 / 临时 worker 与原生自动审查

/threads 和 /history 继续使用只读接口；/use 只保存选择，不调用 thread/resume。收到文字、图片或文件任务后才启动/恢复；turn/completed 后先回传文件，再 thread/unsubscribe 并关闭 App Server 子进程。

/approval auto 使用 workspace-write + on-request + auto_review。这不是无条件允许；高风险请求仍可能被拒绝。不会使用 never 或 danger-full-access。

新配置默认不信任任何网络域名。只有用户在本机配置的精确 HTTPS 域名，并且 App Server 主动提出匹配的策略修订时，Bridge 才会应用；不接受 HTTP、IP、通配符、未列出的子域名或未经服务端提议的规则。第三方图片服务、技能、凭据和运行环境不随仓库提供。

若桌面端正在执行同一会话，TG 会明确报告占用；v0.4.1 起可在二次确认后释放桌面后端并接管。TG 完成并释放后，桌面端可重新进入该会话查看最新上下文，无需退出整个 ChatGPT。

v0.3.1 / 旧版审批行为（已由 v0.4.0 取代）

v0.3.1 的 auto 仅使用 workspace-write + on-request + user，因此仍会把很多请求发到 TG 人工确认。v0.4.0 已改为原生 auto_review，但工作区沙箱、目录保护和未知请求默认拒绝仍保留。

v0.3.0 / 在 Telegram 授权额外目录

/allow /完整/工作目录：显示真实路径及范围，点击确认后才加入目录白名单。/permissions 查看所有授权；/revoke tg_代号 在任务空闲时撤销TG新增授权。初始本机授权不由此命令撤销。

缺少会话目录授权时显示申请入口；命令/文件审批仍在等待时，先点“先授权所需目录”，确认后还须另点“允许本次”。目录授权不等于批准执行，不扩大当前Codex沙箱，不延长原审批时限，也不自动补发失败任务。

授权目录及子目录，持久化至 state/directories.json，直到撤销。保留Token配置。禁止根目录、整个用户主目录、整个桌面/文档/下载目录、系统/凭据/Codex数据/桥接代码和配置路径；拒绝父目录跳转和失效符号链接。不自动扫描或判断项目是否含所有敏感文件，授权前仍需你确认。

以下仅是 v0.3.0 的旧行为：当时已有桌面会话可能长期持有 writer 锁，曾建议 Command-Q 完全退出 ChatGPT。v0.4.0 已改为按任务启动临时 worker 并在完成后释放，不再把退出整个 ChatGPT 作为正常操作步骤；桌面任务正在执行时，TG 会明确提示占用且不会抢锁。

158项离线测试、18项语法检查通过。未替你增加真实目录、未修改Token/代理、未重启服务；真实手机授权和审批执行仍待验证。

v0.2.1 / 之前修复的两项问题

会话不回复：该版本曾使用“仅查看”和“连接并继续”区分预览与恢复。v0.4.0 的按钮已改为“选择会话”：选择只保存会话 ID，发送任务时才临时恢复。未选择会话的文字不会执行或排队，也不会误发到先前预览的其他会话。

代码单独复制：Markdown围栏代码现在单独用Telegram代码块展示。完整短代码提供“复制代码”按钮；超过256 UTF-16单元的代码使用客户端代码块复制/长按复制，超长代码分段并提示合并。未闭合、截断代码不提供一键复制；不会擅自把字符实体改成引号或改写命令。已发送的旧消息不会自动重排，请重新 /history。

按钮的转圈确认和键盘清理改为非阻塞，不影响身份校验、审批期限或一次性决定。网络仍断开时，消息仍可能无法送达；本版没有自动重发任务。112项离线测试通过，手机上的真实点击与复制效果仍待你重启后验证。

01 / 在这台 Mac 上启动

1准备 Codex 与项目

确认 Codex 已正常登录。找到 Codex.app 的位置，或可运行的 codex 可执行文件。

准备要授权的具体项目文件夹。不要选择整个桌面、主目录或下载目录。桥接程序自身的配置目录不能落在授权项目内。

2创建专用 Telegram Bot

在 Telegram 的官方 @BotFather 使用 /newbot，获得 Bot Token。不要与已有 webhook 或其他轮询程序共用这个 Bot。

Token 只在下一步的本机终端输入，不要发到本次聊天。

在 Mac 终端运行下面的入口；也可以在 Finder 打开项目内的 start.command：

git clone https://github.com/lukakai/codex-telegram-bridge.git
cd codex-telegram-bridge
./start.command

启动器使用 PATH 中的 Node 22+；也可通过 CODEX_TELEGRAM_NODE=/绝对路径 指定可信 Node。无需安装 npm 包。已配对用户不要使用 --configure，只需正常重启。

  1. 确认隐私说明，填写 Codex 路径。可直接提供 Codex.app 或 ChatGPT.app 路径，程序会尝试其 Contents/Resources/codex。
  2. 指定与桌面版一致的 CODEX_HOME，默认通常为 ~/.codex。若桌面版使用了其他位置，必须手动填对；程序不会复制登录凭据来猜测路径。
  3. 填写一个或多个已有项目目录与名称。
  4. 隐藏输入 Bot Token，程序检查 Bot 身份与 webhook 状态；不会替你删除 webhook。
  5. 把终端显示的 /start 一次性口令 发到你的 Bot 私聊。在终端核对 Telegram 用户 ID，输入 yes 后才保存配置。
  6. 保留终端运行，等待 Bot 提示“Mac 桥接已待命”。

配置保存为 state/config.json，权限为 600；它包含明文 Token，因此不要上传、分享或提交 state 文件夹。这是文件权限保护，不是 Keychain 加密，也不能隔离同一 macOS 用户下的其他进程。

指令行为

/model / /models选择当前 Codex 返回的模型，支持 /model 模型ID。切换模型时强度重置为该模型自己的默认值。/model default 取消覆盖，但不撤销会话已经采用的模型设置。

模型与强度偏好单独保存在 state/preferences.json，权限600，不修改包含 Token 的配置。设置对本 Bot 后续新任务和恢复后的回复生效，跨会话、重启保留。未选择时沿用会话/配置；任务运行中禁止切换。用 /status 查看当前设置。

03 / 审批与安全边界

程序已经做了什么

  • 绑定 Telegram 数字用户 ID 与私聊 ID，拒绝群聊及未配对用户。
  • 审批绑定请求、会话、任务和消息；仅本次允许，无“全部放行”。
  • 默认 10 分钟超时拒绝。任务完成、断开或中止后按钮失效。
  • 完整命令 / 可用完整 diff 才提供审批。过长详情、无法识别的请求或缺少元数据时拒绝。
  • 检查文件路径、符号链接与移动目标；点击允许时再次检查。
  • 消息先保存偏移再执行，崩溃后不自动重放。代价是极端情况下消息会丢失，需自行核对后重发。

不能据此保证什么

  • 不是“每条命令或每次写文件都审批”。只转发 Codex 实际发出的审批；v0.3.1 可在 /approval 切换为 on-request，未切换则保留原来的 untrusted 策略和沙箱控制，已被 Codex 允许的操作可能直接执行。
  • 项目白名单是会话/目录入口限制，不是任意 shell 命令的硬性防火墙；批准越过沙箱的命令可能影响目录之外。
  • 沿用现有 Codex 环境与配置；其已有工具、MCP 服务或自定义指令仍须你信任。
  • Bot 对话不是端到端加密。查询到的历史文本、任务、回复、审批命令和 diff 会进入 Telegram 云端。
  • 支持基础 MCP 表单确认；远端生物识别、敏感输入、复杂表单、动态工具调用和批量权限提升不受支持，未知交互仍默认拒绝。

04 / 一次真实联调的验收顺序

  1. 先用一个不含敏感内容的测试项目。建议使用独立 Git 仓库，并保存桌面端所有尚未提交的重要工作。
  2. 发送 /projects、/threads，确认看到的是桌面版对应的本地会话；工作目录必须匹配。
  3. 让桌面端保持该会话打开但不要运行重要任务，然后从 TG 选择该会话。看到占用提示后阅读风险说明并确认接管；收到“TG 已接管”后重新发送一句“只总结上下文，不要修改文件”。确认任务完成后释放，再从桌面端重新打开并核对最新上下文。
  4. 用 /new 只列出项目文件，不要修改文件 验证新任务和回复回传。
  5. 仅在受控测试项目中触发一个你理解的审批，先验证拒绝，再验证单次允许；若 Codex 没有产生审批，不应为了测试而关闭沙箱。
  6. 验证 /stop、/release，以及重启后旧按钮失效、旧任务不自动重发。确认测试文件变更与预期一致。
桌面与 TG 不会同时写同一会话。

检测到 writer 冲突时，TG 必须经二次确认才会重启桌面 Codex 后端并接管。这个动作会影响桌面端的所有 Codex 任务、审批和终端，而不只所选会话；桌面审批不会转移到 TG。目标进程不能唯一验证时会拒绝。云端专属或不同 CODEX_HOME 的历史不保证可见。

05 / 检查、排错与测试

找不到 Codex，或历史列表为空

配置向导可接收完整可执行文件路径或 .app 路径；程序不会自动安装另一个 Codex 版本。历史为空时先核对 CODEX_HOME、授权目录和会话 cwd。新版会聚合授权父目录下的子目录历史，不需要逐个添加84个目录。授权范围之外的 worktree 仍须另外授权；已不存在或无法验证的目录不展示，子代理记录不作为独立聊天重复列出。

Mac 睡眠、终端关闭、网络中断

桥接是本机服务，Mac 必须醒着、联网且终端保持运行。不会自动安装开机启动或更改电源设置。重连不会重发已消费的任务；Codex 连接断开后需本机重启。Telegram HTTP 409 表示同一个 Bot 被其他轮询实例占用。新版将长轮询等待从25秒缩短为10秒，并记录 TIMEOUT、ECONNRESET 等脱敏错误类型、累计失败数、限制重复日志；这只是提升兼容性，并不能证明截图中的网络问题已修复。未修改你的系统代理或网络配置。

协议不兼容或审批被拒绝

app-server 协议随版本变化，包含实验性接口。--doctor 只检查配置、Bot 与初始化握手，不代表所有会话/审批接口可用。当前实现不擅自降级到无审批或全权限模式。缺少完整 diff、移动目标无法核验、长期授权请求及未知协议默认拒绝。

重新配置、诊断与运行离线测试

在项目目录的终端中运行：

node main.mjs --configure
node main.mjs --doctor
node verify.mjs

如果 Node 不在 PATH，可用启动器执行前两项，例如 /bin/zsh "/完整路径/start.command" --doctor。离线测试只使用模拟 Codex / Telegram，不登录真实账号，也不执行项目任务。测试产生的小型 test/.fixture-* 合成目录保留供检查，不打包入发布文件。
